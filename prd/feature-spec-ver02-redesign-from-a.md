# 병원 진료 대본 서비스 — PRD (ver02 새 방향, A부터)

### 1) 한 줄 정의
증상이 있는데 어느 과에 가야 할지, 진료실에서 뭐라고 말해야 할지 모르는 사람(처음 아픈 본인, 또는 부모님 대신 정리해주는 자녀)에게, 채팅으로 6단계 입력을 받아 **진료과 추천 1~3위 + 그대로 읽을 대본 카드 + 질문 3개 + 찍어둔 사진(날짜순) + 진료 후 메모 이월**을 만들어 준다. 진단·처방이 아니라 **증상 정리 + 질문 준비 도구**다.

### 2) 타깃 사용자
- **주 사용자**: 증상이 있는데 어느 과인지, 뭐라고 말할지 모르는 사람. 예시: 30대 직장인이 손 오돌토돌+열 3일째인데 피부과인지 내과인지 몰라 검색만 하다가 못 가는 상황.
- **부 사용자**: 부모님 진료 기록을 대신 정리해주는 자녀(프로필 기능으로 여러 명 관리).
- **프로필 입력**: 호칭, 나이(65세 기준 노인주의 판단용), 알레르기, 만성질환까지 미리 받되, 처음 진입 시 최소한(호칭+나이)만 묻고 나머지는 "나중에 채움" 허용. 약 이름은 프로필이 아니라 대화 4번째 턴에서 받는다.

### 3) 문제
1. 아프면 어느 과에 가야 하는지부터 모름(내과인지 소화기내과인지, 피부과인지 내과인지).
2. 진료실에 들어가면 증상을 어떤 순서로 말해야 할지 몰라서 두서없이 말하고, 의사가 묻는 것만 답하고 나옴.
3. 물어보려던 걸 못 물어보고 "네" 하고 나옴.
4. 다음 진료 때 지난번에 무슨 약을 먹었는지, 뭐라고 진단받았는지 기억이 안 나서 처음부터 다시 설명.
5. 기존 서비스는 약 이름·진료과처럼 이미 병원에 다녀온 사람만 아는 걸 미리 입력하라고 해서 처음 아픈 사람은 못 씀.

### 4) 트리거
- 사용자가 **직접 URL로 접속**. 알림 없음.
- 대표 순간:
  1. 매일 야근으로 병원 못 가다가 증상 며칠 이어져 "이제 가야겠다" 싶은 날 막막한 순간
  2. 병원 대기실에서 순서 기다리며 의사에게 조리있게 말할 내용 정리하는 순간
  3. 피부처럼 눈에 보이는 증상이 밤·아침 다르게 보여 그때그때 찍어 둬야겠다 싶은 순간
  4. 진료 끝나고 나와서 의사가 뭐라 했는지 잊기 전에 적는 순간(다음 진료에 참고)

### 5) 핵심 기능

**P0 (최대 4개)**

| # | 기능 | 비고 |
|---|------|------|
| P0-1 | 채팅 입력 + 추천 칩 5~7개, 마지막 칩 "잘 모르겠어" | 한 번에 하나씩 묻기. 입력창 위 칩, 없으면 타이핑 |
| P0-2 | 6단계 되묻기: 어디가 아파 / 어떻게 아파 / 언제부터 / 먹는 약 / 해본 것 / 질문 3개 | 순서는 고정하되 칩 내용은 부위·상황에 따라 동적 |
| P0-3 | 출력: 진료과 1~3위(규칙표, 애매하면 내과·가정의학과) + 대본 카드 + 질문 3개 + 사진 날짜순 배치 + 복사 버튼 + PDF 저장 버튼(브라우저 인쇄로) | 응급이면 대본 대신 119/즉시 병원 권장만 |
| P0-4 | 진료 후 메모 입력 → 다음 대본 5번(했던 것/이전 진료)에 자동 반영, 처방약 입력 연계 | 비회원 localStorage, 회원 Supabase 암호화 |

**P1**

- 약 이름 공공데이터 확인(e약은요·DUR — 기존 절차 유지)
- 낱알식별: 모양·색·각인 텍스트로 후보 카드 표시(사진 안 씀, 식약처 낱알식별 API 텍스트 파라미터)
- 왼쪽 사이드 진료 기록 열람(회원은 Supabase에서, 비회원은 localStorage에서)
- 노인주의(65세 이상 시 DUR 조회)
- 응급 신호 걸러내기(어느 단계에서든 119 권장으로 멈춤)
- 약 API 실패해도 대본은 나온다

### 6) 스킬 매핑

| 기능 | 사용하는 예선 스킬/데이터 경로 | 이식 방식 |
|------|-------------------------------|-----------|
| 대본 생성(6항목 순서·질문 3개·읽기 문장) | SKILL.md hospital-visit-ready (Solar Pro 4 호출) | `/api`가 Solar Chat Completions API 호출, model `solar-pro4`. 프롬프트는 스킬 원칙(진단 말고 정리·권유만, 확신 말고 권유) 그대로 이식 |
| 약 이름 확인·효능군 중복·병용금기·노인주의 | SKILL.md 복용 약 확인·점검 API 절차(e약은요, DUR) | `/api`가 공공데이터포털 API 호출(인증키는 Vercel 환경변수, 값 노출 금지). 절차는 스킬 그대로: e약은요 이름 확정 → 효능군 중복 → 병용금기(적은 쪽만 스캔) → 노인주의(65세+일 때만) |
| 낱알식별 | SKILL.md 복용 약 확인·점검 API 절차 중 낱알식별(텍스트 파라미터) | `/api`가 공공데이터포털 낱알식별 API를 모양·색·각인 텍스트로 호출, 후보 카드를 프론트에 내려줌 |
| 진료과 추천(1~3위) | 새 규칙표(별도 로직) — SKILL.md에는 없는 신규 항목 | `/api` 또는 프론트에서 규칙표 기반으로 진료과 1~3위 산출. 규칙표는 PRD 부속 문서로 따로 둠 |
| 응급 신호 필터 | SKILL.md 2) 즉시 병원 가야 하는 신호 대조 | `/api`(또는 프론트)에서 응급 신호 체크리스트 대조, 하나라도 걸리면 119/즉시 병원 권장만 출력 |

**스킬 변경내역(PRD 스킬 매핑에 기재해야 할 것):**
- 기존 SKILL.md는 텍스트 자유입력 → 6항목 대본+질문 3개(글자)였다.
- 이번 방향에서 **수정·확장한 부분**:
  1) 입력 방식: 부위 그림 클릭 → 채팅+추천 칩 5~7개+마지막 칩 "잘 모르겠어" — SKILL.md 입력 방식 시정
  2) 언제부터: "확실한 날짜 필수" → 날짜 범위 허용(오늘/어제/2~3일 전/일주일쯤/2주 넘게/한 달 넘게/잘 모르겠어), 모르면 대략 한 번 되묻고 "기억 안 남"으로 적되 **날짜 추정·만들어내지 않음**
  3) 응급: 기존 "즉각 119 후 중단" → **어느 단계에서든** 119 권장으로 확대
  4) 되묻기 순서·내용: 6단계(어디가/어떻게/언제부터/먹는 약/해본 것/질문 3개)로 재편, 부위별 동적 칩 추가
  5) 약: 기존 e약은요·DUR 유지 + 낱알식별(텍스트 파라미터) 추가 + 최근 처방약 불러오기(이전 진료 메모 있을 때만)
  6) 출력: 기존 글자 대본+질문 3개 → 진료과 1~3위 + 대본 카드 + 질문 3개(칩으로 이대로/하나 바꿀래/직접 추가) + 사진 날짜순 + 복사 + PDF(브라우저 인쇄)
  7) 진료 후 메모 → 다음 대본 5번 자동 반영(기존 유지) + 처방약 입력 연계

### 7) 입력·출력

**입력(처음 온 사람 화면)**
- 채팅 화면. 에이전트가 한 번에 하나씩 묻고, 입력창 위에 추천 칩 5~7개. 칩 누르면 그 말이 대화 입력으로 들어감. 칩 없으면 타이핑. 마지막 칩은 항상 "잘 모르겠어".
- 왼쪽 위 로고 밑 펼치기 아이콘 → 진료 기록 왼쪽 사이드 열림.

**6단계 입력**

1. **어디가 아파?** 칩: 머리/눈/귀·코·목/가슴/배/허리·관절/피부/여러 군데. 피부·눈처럼 보이는 부위면 "사진 찍어 두라는" 칩 하나 붙음. 입력창 옆 카메라 버튼은 항상 있음.
2. **어떻게 아파?** 부위별 동적 칩. 피부→가려워/빨갛게 올라와/물집/부어/진물. 배→쓰려/더부룩해/찌르듯이/설사 해. 통증 계열→어떨 때 심해지는지 한 번 더 묻고, 피부 계열이면 건너뜀.
3. **언제부터 아팠어?** 칩: 오늘/어제/2~3일 전/일주일쯤/2주 넘게/한 달 넘게/잘 모르겠어. 모르면 대략 한 번 되묻고, 그래도 모르면 "기억 안 남"으로 적음. **날짜를 추정·만들어내지 않음.**
4. **먹는 약.** 칩: 최근 처방약 불러오기(이전 진료 메모 있을 때만 보임), 약 이름 입력, 모양·색·각인 찾기(텍스트, 식약처 낱알식별), 안 먹어. 사진 안 씀. 이름 잡히면 e약은요+DUR 원래 절차대로.
5. **낫게 하려고 해 본 것.** 병원 다녀왔으면 "뭐라고 했는지" 이어서 묻고 기록 저장.
6. **질문 3개.** 사용자에게 쓰라고 하지 않고, 지금까지 답으로 의사 질문 3개를 먼저 만듦. 칩: 이대로 / 하나 바꿀래 / 직접 추가.

**출력**
- **응급 신호 걸림**: 어느 단계에서든 119 혹은 즉시 병원 방문 권장만 출력, 대본 중단.
- **정상 출력**: 대본 카드 형태
  - 진료과 1~3위(규칙표, 애매하면 내과·가정의학과)
  - 그대로 읽을 대본(6항목 순서)
  - 질문 3개
  - 찍어 둔 사진 날짜순 배치(옆에)
  - 복사 버튼, PDF 저장 버튼(브라우저 인쇄로)
- 카드 아래: 진료 후 메모 입력. 적으면 다음 대본 5번에 자동 반영.

**사진 처리**
- 업로드 전 브라우저에서 크기 줄이기 + 썸네일 생성 → 둘 다 암호화 → Supabase 저장(회원) 또는 localStorage(비회원).
- 읽기 시 supabase-js로 목록 받아오고 기기 키로 복호화 → img 표시.

### 8) 필요 설정

**표 A — 배포 연결 (값 취급 없음)**
- Vercel git 연동: `harimchung/hospital-visit` repo. dev→preview, main→production.
- 프론트(팀원)와 백엔드(/api)는 같은 repo의 별도 경로로 구성하거나, /api만 네가 맡음. frontend는 Vite+React로 이미 테스트 배포 중.

**표 B — 서비스 키 (Vercel 환경변수, 값 금지, 이름·용도·발급처만)**

| 키 이름 | 용도 | 발급처 |
|---------|------|--------|
| `UPSTAGE_API_KEY` | Solar Pro 4 호출(대본 생성·검수) | Upstage Console |
| `PUBLIC_DATA_API_KEY` | 공공데이터포털 인증키(e약은요·DUR·낱알식별 통합 1개) | 공공데이터포털 |
| `SUPABASE_URL` | Supabase 프로젝트 연결 주소 | Supabase 대시보드 |
| `SUPABASE_ANON_KEY` | /api에서 Supabase 클라이언트 인증용(RLS 적용) | Supabase 대시보드 |

- 위 4개는 Vercel 환경변수, /api에서만 읽음. 클라이언트 소스·응답 JSON에 값 0.
- anon 키는 브라우저에 안 감(프론트가 Supabase SDK 직접 안 씀). /api가 중계.

**표 C — 사용자 프로필 (웹 화면 입력 → localStorage 저장, 재방문 시 묻지 않음, 초기화 버튼 제공)**

| 필드 | 필수/선택 | 용도 |
|------|-----------|------|
| 호칭(아버지/어머니 등) | 선택 | 프로필 카드 표시 |
| 나이 | 선택 | 65세 이상 시 노인주의 조회 판단용 |
| 알레르기 | 선택 | 대본 생성 시 있으면 반영, 없으면 "확인 후 적기로 남김" |
| 만성질환 | 선택 | 위와 동일 |

- 처음 진입 시 호칭+나이만 묻고, 알레르기·만성질환은 "나중에 채움" 허용.
- 약 이름은 프로필이 아님. 대화 4번째 턴에서 받는다.

**기기별 비밀(서버 못 읽음, 브라우저에만):**
- 브라우저 Web Crypto로 생성한 대칭키(AES-GCM 권장). 기기에만 둠.
- 암호화 대상: 대본, 답, 진료 후 메모, 사진 바이너리.
- 평문 필드: 날짜 라벨, 부위 라벨만 Supabase에 둠(기록 목록 조회용).

### 9) 데이터 규칙
- 출처·기준 시각 표기: 공공데이터 출처(식품의약품안전처, 공공데이터포털) 표기. 기준 시각은 가능하면 표기(없으면 '확인 불가').
- 없는 값은 '확인 불가', 추정 금지.
- 키·프록시 주소는 서버(/api)에만. 클라이언트 소스·응답 JSON에 키 0.
- 최소 권한: Supabase RLS(user_id 기준 자기 기록만 읽고 씀). non-member는 Supabase 안 탐.
- 개인정보: 비회원 localStorage-only. 회원도 서버 평문 못 읽게(기기 암호화).
- 진료 후 메모·처방약·대본은 암호화 payload로 Supabase 저장. 평문으로 날짜·부위만 둠.
- 사진: 업로드 전 리사이즈+썸네일 생성 후 암호화. 읽을 때 프론트 복호화.

### 10) 성공 기준 (데모 시나리오 검증 가능 조건)

**시드 시나리오 (회원·비회원 둘 다 확인)**

**비회원(시크릿 창 테스트 포함)**  
1. 시크릿 창에서 URL로 처음 접속 → 로그인 없이 진료 시작 가능.  
2. 6단계 채팅 입력(부위 칩+날짜 범위+약 이름 텍스트+사진 없이) 완료 → 대본 카드 출력.  
3. 출력에 진료과 1~3위 + 대본 + 질문 3개 + 복사 버튼 + PDF 저장 버튼 존재.  
4. 진료 후 메모 입력 → 다음 대본 5번에 자동 반영(로컬 재방문).  
5. 브라우저 저장값 삭제 후에도 재시작 시 안내가 스스로 나오고 최소 기능 동작.

**회원**  
1. Supabase Auth로 로그인 → /api가 Supabase RLS 적용.  
2. 6단계 입력(사진 업로드 포함) → 대본 카드 출력. 사진 날짜순 배치.  
3. Supabase에 암호화 저장(서버 평문 못 읽음, 평문 날짜·부위만 확인 가능).  
4. 기록 목록 왼쪽 사이드에서 열람, 이전 대본 불러오기 가능.

**공통**
- 응급 신호 입력 시 어느 단계에서든 119/즉시 병원 권장만 나오고 대본 중단.
- 약 API 실패(e약은요 0건 등)해도 대본은 나온다.
- Solar가 확신성 문장("이건 감기네요") 대신 권유 문장("감기로 의심되는데, 이비인후과를 가보는 게 어때요?")으로 출력.

### 11) 제외 범위
- 의사 진단·처방 대행 아님.
- 복용 약 임의 중단·조정 조언 안 함.
- 법령·규정상 금지 콘텐츠(차별·혐오·폭력·음란·타인 명예훼손·타인 개인정보 무단 포함 등) 미포함.
- 카카오톡 전송은 이번 범위에서 제외(ver02 이후 재검토 가능 — 기존 ver01에서 보류한 것과 일관).
- 기기 간 키 공유 안 함(다른 기기에서 이전 기록 복호화 불가 — 원본 요청 "서버 못 읽게" 취지상 제약).
- 비회원 Supabase 저장 안 함(localStorage-only).
- 프론트(Vite+React)는 팀원 담당. 나는 PRD, /api, 진료과 규칙표, Supabase 테이블·RLS까지.
