# 병원 진료 대본 서비스 — 기능명세서 (ver01, 회의용)

> 대상: 부모님(고령층) 진료를 앞둔 자녀가, 전화 전에 물어볼 내용을 순서대로 정리하고 의사에게 보여줄 대본을 만드는 서비스.
> 범위: ver01 = MVP 1주기. 9/13 새벽 목표.
> 주의: 이 서비스는 의료진의 진단을 대체하지 않는다. 증상을 정리하고 질문을 준비하는 도구다.

---

## 1. 한 줄 정의

부모님의 병원 진료 전에, 자녀에게 **전화로 물어볼 6단계 질문 흐름**을 안내하고, 입력이 끝나면 의사에게 그대로 보여줄 수 있는 **읽기 전용 대본(6항목 + 질문 3개)**을 만들어 준다.

---

## 2. 타깃 사용자

- 주 사용자: 부모님(고령층)을 모시고 병원 가는 자녀/부양자.
- 사용 상황: 부모님이 병원에 가기 전, 혹은 병원 도착 후 대기 중에 자녀가 전화/메신저로 부모님께 물어보고 정리할 때.
- 특징: 의료 지식이 없어도 쓸 수 있어야 하고, 입력은 짧게·단계별로 받을수록 좋다.

---

## 3. 핵심 가치 (왜 만드는가)

- 병원 진료 전, "뭘 물어봐야 하지?"를 고민하지 않게 해준다.
- 의사에게 말할 순서(언제부터 → 어떻게 변했나 → 심해지는 상황 → 약 → 이미 해본 것 → 질문 3개)를 정리해 준다.
- 진료 후에는 의사가 한 말을 메모로 남겨, 다음 대본에 이어서 쓸 수 있다.

---

## 4. 서비스 흐름 (ver01)

### 4-1. 첫 화면

- 관리 대상 프로필(부모님) 목록: 아이콘 + 호칭 카드 형태.
- 프로필이 없으면 중앙 + 버튼 또는 **"프로필 없이 바로 시작"** 버튼.
- "바로 시작" 시 진료 흐름으로 바로 진입 가능.
- 저장 시점에 호칭을 묻거나, 첫 진입 시 **"부모님"** 프로필을 자동 생성할 수 있다(ver01 안 확정).

### 4-2. 프로필 관리 (최대 3개)

- 부모님을 여러 명 관리할 수 있도록 프로필을 3개까지 등록.
- 등록 항목: 호칭(아버지/어머니 등), 나이.
- 데이터는 브라우저 localStorage에만 저장. 서버 전송 없음.

### 4-3. 6단계 전화 전 질문 흐름

화면에 **"부모님께 전화 걸기 전에 이 순서대로 물어보세요"** 라는 안내와 함께, 6단계 순서도(클릭 가능 단계 카드)를 보여 준다. 각 단계를 클릭하면 질문 문안 + 되묻기 문안 + 입력칸이 나온다.

| 단계 | 내용 | ver01 입력 방식 |
|---|---|---|
| 1. 언제부터 | 증상이 언제 시작됐는지 | **날짜 필수.** "좀 됐어요" 같은 모호한 답변은 되묻기 문안(예: "추석 전이었어요, 후였어요?")으로 날짜를 확정. 날짜가 확정되기 전에는 다음 단계로 못 넘어감. |
| 2. 어떻게 변했나 | 처음과 지금의 차이 | 자유 텍스트 |
| 3. 어떨 때 심해지나 | 어떤 상황에서 더 심해지거나 나아지는지 | 자유 텍스트 |
| 4. 복용 약 | 현재 복용 중인 약 | **이름 텍스트 입력만.** 사용자가 부모님에게 받은 약 봉투·약 사진을 보고 직접 텍스트를 입력. (ver01에서는 OCR·비전 모델 없음, 사진 업로드/글자 입력 필드는 사용자가 직접 보고 입력하는 용도로만 둘 수 있음) |
| 5. 이미 해본 것 | 이미 해본 조치·약·이전 진료 내용 | 자유 텍스트. 이전 진료 메모가 있으면 자동 채움. |
| 6. 묻고 싶은 것 | 의사에게 묻고 싶은 것 | 여러 개 입력 가능. 3개로 좁히는 것은 뒤에서 AI가 처리. |

### 4-4. 복용 약 이후 — 대본 생성

6단계 입력이 끝나면, **Solar Pro 4(Upstage Chat Completions API, model `solar-pro4`)**를 호출하여 다음을 생성한다.

- 6항목 대본 (의사에게 읽을 수 있는 문장 형태)
- 묻고 싶은 것 3개 (사용자가 여러 개 입력한 것 중 정리)
- 근거/검증 성격의 요약 (진단이 아니라, 질문 형태로 우려 사항을 간접적으로 정리)

이 서비스는 진단을 하지 않는다. 증상을 정리하고 질문을 준비하는 것이 역할이다.

### 4-4. 결과 화면

- 의사에게 보여줄 내용을 글자 형태로 출력. 길어도 괜찮다.
- 오른쪽 위에 **복사 버튼**이 있다.
- **카카오톡 전송은 ver01에서 보류.** 대신 웹 Share + 복사로 대체한다.

### 4-5. 진료 후 메모·이어서 쓰기

- 결과 화면 아래에 **"진료 후 메모 남기기"** 입력란이 있다.
- 자녀가 부모님과 다시 통화하면서 "의사가 뭐라고 했는지"를 대략 적어 저장한다.
- 저장된 메모는 **localStorage**에 남는다.
- 다음 대본 생성 시, 5단계(이미 해본 것/이전 진료)에 자동으로 반영된다.
- 못 물어본 질문도 함께 이월하여 다음 대본에 넣을 수 있다.

---

## 5. 약(약물) 정보 처리 정책

- 공공데이터포털 API는 허용된다.
- ver01에서는 **약 API 호출을 하지 않는다.** 복용 약은 이름 텍스트 입력만 받는다.
- 약 봉투·약 사진을 사용하더라도, ver01에서는 **OCR이나 비전 모델을 쓰지 않는다.** 사용자가 사진을 보고 직접 텍스트로 입력한다.
- 낱알식별(API) 기능은 ver01에서 제외. 각인·모양·색 등 텍스트 파라미터 기반 공공데이터 API는 향후 검토 대상(ver02 이후).
- ver02부터 SKILL.md 순서대로 활용할 수 있다: e약은요 이름 확정 → 효능군 중복 → 병용금기 → 노인주의(65세 이상). 약 조회가 실패해도 대본은 나와야 한다.
- 공개 출처는 표기한다: 식품의약품안전처, 공공데이터포털.

---

## 6. 개인정보·보안 (간단)

- 프로필 정보(호칭, 나이), 진료 메모 등은 **브라우저 localStorage에만 저장**. 서버로 전송하지 않는다.
- Upstage API 키는 **Vercel 환경변수(`UPSTAGE_API_KEY`)**로만 관리. 클라이언트 소스·응답 JSON에 키가 노출되지 않는다.
- 이 서비스는 사용자의 개인정보를 동의 없이 수집·노출하지 않는다.

---

## 7. ver02·ver03에서 확장 가능한 부분 (참고)

- ver02: 약 API 연동 본격화(e약은요 이름 확정, 효능군 중복, 병용금기, 노인주의), 약 이름 확정 플로우 완성, 낱알식별 텍스트 파라미터 검토.
- ver03: 프로필 전환 UX 개선, 이전 대본/진료 메모 이력 보기, 예약·리마인더 등 부가 기능, 제출물(포스터·발표자료·데모 영상) 완성.
- 카카오톡 전송은 ver02 이후 재검토 가능.

---

## 8. 제한·범위 밖

- 의사의 진단·처방을 대신하지 않는다.
- 복용 약을 스스로 중단하거나 조정하라고 조언하지 않는다.
- 법령·규정상 금지되는 콘텐츠(차별·혐오·폭력·음란·타인 명예훼손·타인 개인정보 무단 포함 등)는 포함하지 않는다.

## 10. 회의용 요약 (30초)

- 누구에게: 병원 가는 부모님을 모시는 자녀.
- 무엇을: 전화 전 6단계 질문 → 의사 대본 + 질문 3개 생성.
- 어떻게: 웹 브라우저에서 단계별로 입력, 결과는 복사해서 사용.
- 약은 ver01에서 이름만 텍스트 입력(OCR·비전 모델 없음). 약 API는 ver02부터.
- 진료 후 메모는 브라우저에만 저장, 다음 대본에 자동 연결.
- Solar는 서버에서 호출, API 키는 클라이언트에 노출되지 않음.
- 진단·처방 대행 아님. 질문 준비 도구.
